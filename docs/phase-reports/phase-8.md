2. **Flaky docs-install test: cause found, not a product bug.** `gradlew clean build` deletes the jar folder that the api container bind-mounts; the download URL then returns 404 until the api is recreated, and Chromium names a download after the URL (`latest.jar`). The API always sends the versioned filename when a jar exists. The test now checks the endpoint first and fails with the real cause. 40/40 passes with a healthy stack. Rule: after a clean Gradle build, `docker compose up -d --force-recreate api` (or build without `clean`). On a server, replace jars inside `agent-jars/`, don't recreate the folder.
